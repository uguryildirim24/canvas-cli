## 4. The two coordinator decisions

### SPEC §19 item 27 — drop `discussions --announcements` (`d9f0c25`)

The request is pinned at `only_announcements=false`, so Canvas never returns
an announcement through it and `--announcements yes` could never show one.
The flag is gone from clap, from the dispatch, from the command, and from the
README row. The human table closes with a line naming `canvas announcements`,
so a reader is told where announcements are instead of taking a short list
for the whole course feed.

`is_announcement` stays in `discussions@1` and `discussion@1`: Canvas sends
it on a topic, so it is a topic property, not a filter.

The wiremock fixture had mounted an announcement in the topics listing, which
the real endpoint cannot return. That fixture row is dropped and the listing
snapshots follow. The test now asserts the listing holds only non-announcement
topics and that the table points at `canvas announcements`.

### SPEC §19 item 28 — `replies_page` and `replies_total` (`7bae43c`)

An out-of-range `--page` returned `replies: []` beside
`replies_coverage.complete = true`, which reads exactly like a thread nobody
answered. `discussion@1` gains two additive fields:

* `replies_page` — the window shown, 1 when `--page` is absent;
* `replies_total` — the replies the covered set holds across every page.

An empty window beside a non-zero total is a page past the end; a total of 0
is a thread with no replies. The out-of-range page stays **exit 0**, as the
coordinator reading says: the set is covered, the window is simply beyond it.
The human line names the window too. Nothing existing is renamed, and the
registry fixture gains the two fields without changing a value.

New test `a_replies_page_past_the_end_is_empty_at_exit_zero` asserts page 1,
the empty page 2 at exit 0 with `replies_total` 3, and the zero case.
