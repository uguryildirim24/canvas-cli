# Adversarial review of SPEC v0.4

Verdict: **FIX-THEN-SHIP**; a blocker remains in the new submission POST failure classification (R4-B01).  
Recovery: Text/URL server matches are now honest; file-ID attribution and journal creation/completion still need narrower guarantees.  
Downloads: The install mutex and normal clobber path improve safety; interrupted moves and the new manifest database need a complete recovery/containment contract.  
Cache and auth: Durable epochs fix the prior invalidation gap; field-group clocks, credential activation, and local command selection retain smaller defects.  
Acceptance: Fix the blocker and the affected feature contracts before their acceptance tests; the owner's confirmed Canvas access remains resolved.

Reviewed on 2026-09-09 against `docs/SPEC.md` v0.4, SHA-256 `24ac18f70d584dd636a477a3a0781e751e2b061844d837f29efcc431679fb369`. Line numbers below refer to that file. This covers all 21 round-3 findings and all 35 earlier IDs marked partially resolved in [round 3](spec-v0.3-review.md). Appendix E was checked against the substantive sections.

This is a specification/source review. No code, account operations, submissions, downloads, platform builds, or runtime tests were performed. API checks were restricted to new claims: notably file-ID attribution and the meaning of a failed submission response. Unchanged behavior is identified below. Primary Canvas evidence uses [the same pinned commit][canvas-commit]. Counterexamples are deductions from the specification and source, not observed failures on the owner's account.

“Resolved” means the prior contract defect is corrected or explicitly narrowed, not that an implementation passed tests. A partial resolution can have only a MAJOR or MINOR residual; the severity of an old ID is not automatically assigned to a different new defect.

## Acceptance focus

The tables above are the requested review, not implementation changes. The smallest useful follow-up evidence is targeted at the remaining counterexamples:

- Submission: committed POST followed by an error response; another client first using fresh upload IDs; two simultaneous new journals; killed owner in planned; confirmed success before receipt creation; failed text readback; old unknown operation followed by a new confirmed attempt.
- Download: crash before and after each move-marker/rename/commit boundary with an occupied same-size target; two recoverers/installers; manifest/sidecar containment and newer schema handling.
- Cache/auth/transport: out-of-order partial observations, absent can_submit, credential activation failures, concurrent env-binding writes, every local selection exception, upload completion handoff, and governor bootstrap/recovery sequences.
- Output/calendar/lanes: nullable/extra-file receipt variants, structured reconciliation candidates, the 23-hour all-day warning, and M2-b acceptance after completed M1-c integration.

The owner's already-confirmed ability to access Canvas is not reopened. The verdict is based on the remaining specification defects, with **1 new BLOCKER, 11 MAJOR findings, and 3 MINOR findings**; it does not assert that any implementation or account operation failed.
