# Adversarial review of SPEC v0.1

Verdict: **FIX-THEN-SHIP**; v0.1 is not ready to serve as an implementation contract.
Risk 1: The deadline and download paths can silently omit work or materials while claiming completeness.
Risk 2: The grade calculator and target solver can give materially wrong answers, including with ordinary drop rules and extra credit.
Risk 3: Account selection, submission recovery, and filesystem writes lack safeguards needed to prevent wrong-account actions, lost receipts, or overwritten files.
Release gate: Resolve the blockers and validate the reduced v1 against adversarial fixtures; Rolf confirmed that access works during this review.

Reviewed on 2026-09-09 against all three `docs/research/*.md` inputs, the live [Canvas API documentation][api], and public Canvas source at commit [`1c9f0bb8013ed69c4f2efe11fd483025469b7e6c`][canvas-commit]. Source line references below use that pinned commit. This is a documentation/source review: no authenticated Lasell requests, submissions, downloads, benchmarks, or implementation tests were performed by the reviewer. Rolf confirmed during the review that access works; Lasell access is therefore not listed as an outstanding blocker. This confirmation does not establish every endpoint's permissions or the deployed grade-calculation behavior. The public source snapshot is not proof of Lasell's deployed version or settings. Research claims marked “verified” were treated as claims to check, not as authority.

Severity: **BLOCKER** prevents safely implementing or releasing a promised core capability; **MAJOR** causes incorrect behavior or leaves a substantial implementation decision unresolved; **MINOR** is a narrower contract or documentation defect. Within each severity, findings follow the requested attack order. Proposed fixes are specification changes for the author; none were applied to `SPEC.md`.

## API cross-check notes

The main student endpoint choices are sound: `users/self`; course list/detail with the listed term, syllabus, teachers, favorites, and total-score includes; assignment lists with own submission; own-submission detail/history/comments/rubric includes; submission-file initiation; the three online submission kinds and `comment[text_comment]`; assignment groups with both `assignments` and `submission` plus effective-date overrides; own enrollments; files/folders/file detail; modules; announcements; planner; and calendar events all have corresponding published routes. The findings concern unsupported includes, incorrect field mappings, pagination, permissions, and omitted behavior: not a need to switch to an instructor gradebook endpoint. See [Users][users], [Courses][courses], [Assignments][assignments], [Submissions][submissions], [Assignment Groups][groups], [Enrollments][enrollments], [Files][files], [Modules][modules], [Announcements][announcements], [Planner][planner], and [Calendar Events][calendar].

The research also overstates novelty: its own profiles describe existing tools that already crawl modules and support structured output (`r2-prior-art.md:47-59,131-142`), while its gap section and Appendix C make broader absence claims. Focus scope on reliable student workflows; novelty is not evidence that grade replication or a general solver is cheap.

## Keep these decisions

- Student-only operations, browser handoff for unsupported submission types/LTI, and no quiz-taking or ID probing.
- Cache-first reads, a real offline mode, explicit freshness, and opaque Link pagination with bounded concurrency.
- OS secret storage as the normal path, local processing, and no third-party token handling.
- Fresh submission preflight, an explicit confirmation plan, receipts, and byte verification: after specifying recovery and the limits of what is verified.
- Module-aware discovery alongside the Files API, with clear lock and partial-coverage reporting.
- Separate API/domain/CLI concerns, pure grade functions, normalized human/JSON output, and Canvas-reported totals taking precedence over unsupported local estimates.
