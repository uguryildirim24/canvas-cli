## Checked and found correct

- **§11 redaction list.** `is_secret_key` covers `Authorization`, `access_token`,
  `upload_params` (the whole object, so every value), `Signature`, `X-Amz-*`,
  `Policy`, `Expires`, `verifier`, `sig`, `token`, in bodies, query pairs and
  headers. Nothing on the list is missing.
- **Idempotence.** Two mechanisms, as the module claims: the manifest lists the
  issued pseudonyms, and every shape is its own fixed point. Proven by the unit
  round trip and by the `record` → `sanitize` → `sanitize` integration test.
  The manifest stores only the issued side; storing the real values as map keys
  would put the identifying data back into the tracked fixture, and the worker
  was right to avoid it.
- **Stable mapping within a set.** One ID maps to one pseudonym across files,
  across the body, the path, the `Link` header and the manifest endpoint list,
  and keeps the JSON type Canvas used.
- **Tracked-directory refusal.** `record` refuses unconditionally rather than
  accepting a `--sanitized` flag. That is stricter than the brief's wording and
  matches its intent — `sanitize` is the only writer there — so I left it.
  The check canonicalizes where it can and falls back to a textual suffix match
  for a directory that does not exist yet, which is the normal case.
- **Headers.** Only the four the client reads are kept. `Set-Cookie` and
  `X-Amz-Signature` are dropped, and the test asserts it.
- **No raw bodies on disk for the cache.** Nothing here writes through
  `canvas-core`'s stores; a fixture is a test artifact and is the exception
  §16 names.
- **Appendix A / MSRV.** No benchmark crate is pinned and none was added; the
  timing is `std::time::Instant` around repeated runs of the real binary, as
  the brief requires. The two new `xtask` dependencies (`url`, `tempfile`) are
  exact-pinned and already in the tree. `cargo +1.88` and `cargo deny` pass.
- **Brief's required tests.** All four groups are present: `record` against
  `wiremock` (headers kept, token absent, tracked directory refused, `Link`
  walk followed), `sanitize` idempotence / stable IDs / every §11 key /
  `MANIFEST.json`, and a `--runs 2 --no-fail` bench smoke run. The smoke test
  writes to a temporary path so it cannot overwrite the tracked report.
- **`bench` exit contract.** Exit 1 on a missed target, exit 0 with
  `--no-fail`, `--runs 0` refused.

## Not fixed, by decision

- **Item-level Appendix B endpoints.** `record` walks collections, not items:
  `assignments/:aid`, `submissions/self`, `files/:id`, `modules/:mid/items`
  and `discussion_topics/:id` would need an ID crawl over the collection
  responses. `--course` exists to bound the walk and SPEC §15 says "no ID
  enumeration", so the line is drawn at collections. Worth revisiting only if
  a recorded set turns out to need per-item responses.
- **`status` is written as a literal `200`.** `send_api_with_headers` returns
  only on success and does not expose the status, and `canvas-api` belongs to
  another lane this round. A `201`/`204` would be recorded as `200`. Harmless
  for the `GET`-only walk; note it if `record` ever posts.
- **Shape collisions in general.** A real value that already matches a
  pseudonym shape is copied through. Fixed for `login_id`, which was the one
  realistic case; `Name N` and `file-N.ext` remain theoretically collidable and
  are kept for fixture readability.
