# Releasing `canvas-lms-cli`

Owner: Rolf. This file is the release runbook. It covers what is in place now,
what the owner has to create once, and the exact commands for each release.

Nothing about this project is published yet. There is **no git remote**, **no
Homebrew tap**, and **no crates.io release**. Everything below is prepared and
verified as far as it can be without them.

## What is in place

| Piece | File | What it does |
|---|---|---|
| Release build | `dist-workspace.toml` | `cargo-dist` 0.32.0: five targets, archives, checksums, Homebrew formula. |
| Release CI | `.github/workflows/release.yml` | Generated by `dist generate`. Do not hand-edit; regenerate. |
| Build hook | `.github/workflows/build-setup.yml` | Injected step that runs `xtask dist-assets` before the archives are built. |
| Man pages, completions | `xtask/src/dist_assets.rs` | `cargo xtask dist-assets --out DIR`, deterministic. |
| Formula fix-up | `xtask/src/dist_assets.rs` | `cargo xtask dist-formula --formula PATH`, adds the install lines dist omits. |
| Versions, changelog | `release-plz.toml`, `CHANGELOG.md` | Conventional commits to a version bump and release notes. |
| Install docs | `README.md` | The three supported install routes. |
| Build profile | `Cargo.toml` `[profile.dist]` | `release` plus thin LTO. |

Targets (SPEC §17): `aarch64-apple-darwin`, `x86_64-apple-darwin`,
`x86_64-unknown-linux-musl`, `aarch64-unknown-linux-musl`,
`x86_64-pc-windows-msvc`.

Every archive carries the binary, both licences, `README.md`, `man/*.1`, and
`completions/`.

### Two things to know before you read further

1. **No installer script.** SPEC §17 does not accept direct archive downloads
   on macOS until the binaries are signed and notarized, so `installers` lists
   only `homebrew`. Turning on the shell installer would cover macOS too.
2. **`dist plan` prints one warning**, on purpose:
   `A Homebrew tap was specified but the Homebrew publish job is disabled`.
   `publish-jobs` is empty because dist 0.32's Homebrew template installs the
   binary and sweeps everything else into `pkgshare`, so its formula would
   leave the man pages and completions unusable. `cargo xtask dist-formula`
   rewrites that sweep into `man1` and the completion directories, and the tap
   commit below is a manual step. If a later dist release lets the formula
   install extra files, add `"homebrew"` to `publish-jobs`, drop the
   `dist-formula` step, and regenerate the CI.

## One-time setup

1. **Create the repository** as `github.com/uguryildirim24/canvas-cli`, then:

   ```sh
   git remote add origin git@github.com:uguryildirim24/canvas-cli.git
   git push -u origin main
   ```

   `repository` in the root `Cargo.toml` already points there. If the URL
   changes, change it there too: the formula and the `cargo binstall` URLs are
   built from it.

2. **Create the tap** as `github.com/uguryildirim24/homebrew-tap`, a public
   repository with a `Formula/` directory.

3. **Create a token for the tap**: a fine-grained personal access token with
   `Contents: read and write` on `homebrew-tap` only. Add it to the
   `canvas-cli` repository as the Actions secret `HOMEBREW_TAP_TOKEN`. It is
   needed only when the Homebrew publish job is turned on; the manual tap step
   below uses your own git credentials.

4. **Check the Actions settings** of `canvas-cli`: Actions enabled, and
   `Settings → Actions → General → Workflow permissions` set to read and write
   so the release job can create the GitHub Release.

## Releasing a version

`release-plz` decides the version from the conventional commits since the last
tag. `feat:` bumps the minor (pre-1.0), `fix:` and `perf:` the patch, and a
`!` or a `BREAKING CHANGE:` footer bumps the minor while below 1.0.

1. **Check the gates on `main`.**

   ```sh
   just check                              # fmt, clippy, nextest, cargo-deny
   cargo +1.88 check --workspace --all-targets
   dist plan
   ```

2. **Bump the version and write the changelog.**

   ```sh
   release-plz update
   ```

   This edits `Cargo.toml`, `Cargo.lock`, and `CHANGELOG.md`. Read the
   changelog, fix the wording, and commit:

   ```sh
   git commit -am "chore(release): v0.2.0"
   git push
   ```

3. **Tag it.** The tag drives everything; `release.yml` triggers on a tag that
   looks like a version, and on nothing else except a pull request, where it
   stops after `dist plan`.

   ```sh
   git tag v0.2.0
   git push origin v0.2.0
   ```

4. **Watch the run.** `plan` → `build-local-artifacts` (five targets) →
   `build-global-artifacts` (formula, source tarball, checksums) → `host` →
   `announce`. The GitHub Release ends up with the five archives, their
   `.sha256` files, `sha256.sum`, `source.tar.gz`, and `canvas-lms-cli.rb`.

5. **Update the tap.** Take the formula from the release, add the install lines,
   and commit it:

   ```sh
   gh release download v0.2.0 --repo uguryildirim24/canvas-cli \
     --pattern canvas-lms-cli.rb --dir /tmp
   cargo xtask dist-formula --formula /tmp/canvas-lms-cli.rb
   brew style --fix /tmp/canvas-lms-cli.rb        # optional
   brew audit --strict /tmp/canvas-lms-cli.rb     # optional

   git clone git@github.com:uguryildirim24/homebrew-tap.git /tmp/homebrew-tap
   cp /tmp/canvas-lms-cli.rb /tmp/homebrew-tap/Formula/canvas-lms-cli.rb
   git -C /tmp/homebrew-tap commit -am "canvas-lms-cli 0.2.0"
   git -C /tmp/homebrew-tap push
   ```

6. **Verify the install on a clean machine**, which is the M5-b acceptance:

   ```sh
   brew install uguryildirim24/homebrew-tap/canvas-lms-cli
   canvas version                 # version, commit, target
   man canvas                     # and man canvas-submit
   canvas completions zsh | head  # the archive script is already installed
   brew test-bot --only-formulae ... # optional, in the tap
   brew uninstall canvas-lms-cli
   ```

   Then check the other two routes:

   ```sh
   cargo binstall canvas-lms-cli   # needs the release archives only
   cargo install canvas-lms-cli    # needs crates.io, see below
   ```

## crates.io

`cargo install canvas-lms-cli` needs the crate published, and it is not.
`canvas-lms-cli`, `canvas-api`, and `canvas-core` all set `publish = false`,
and a publishable binary crate cannot depend on unpublishable path
dependencies. To publish:

1. Give `canvas-api` and `canvas-core` a `description` and
   `repository.workspace = true`, and drop `publish = false` from all three.
2. Give the path dependencies versions in the root `Cargo.toml`, for example
   `canvas-api = { path = "crates/canvas-api", version = "0.1.0" }`.
3. Publish bottom-up: `canvas-api`, `canvas-core`, then `canvas-lms-cli`.
4. Add `"cargo"` to `publish-jobs` in `dist-workspace.toml`, set the
   `CARGO_REGISTRY_TOKEN` secret, and regenerate the CI, so later releases
   publish themselves.

The name `canvas-lms-cli` was free on crates.io on 2026-09-09 (SPEC §4).
`canvas-cli` is taken.

## Running the release build locally

```sh
cargo xtask dist-assets --out target/dist-assets
dist plan                                   # all five targets, no build
dist build --artifacts=local --target "$(rustc -vV | sed -n 's/^host: //p')"
dist build --artifacts=global               # formula, source tarball, checksums
cargo xtask dist-formula --formula target/distrib/canvas-lms-cli.rb
```

`just dist-assets`, `just dist-plan`, and `just dist-build` wrap the first
three. Cross-compiling the other four targets locally needs `cargo-zigbuild`
and `cargo-xwin`; CI has them, so pass `--target` for the host instead.

A local `dist build --artifacts=global` produces a formula with no `sha256`
lines, because there is no release to hash. That is expected off CI.

## Upgrading the tooling

`cargo-dist` and `release-plz` are pinned (SPEC Appendix A: 0.32.0 and
0.3.164). `cargo-dist-version` in `dist-workspace.toml` must match the `dist`
binary, or `dist` refuses to run.

```sh
dist selfupdate --version 0.33.0   # also reruns `dist init`
dist generate                      # rewrite release.yml
dist plan                          # must be clean
```

After any dist upgrade, re-read the generated Homebrew formula and rerun the
`xtask dist-formula` tests: they fail on purpose when the template changes.

## Verified for M5-b, 2026-09-10

Run on the owner's machine, `aarch64-apple-darwin`, with no remote and no tap:

- `dist plan` — all five targets, every archive listing `canvas`, `man`, and
  `completions`.
- `dist build --artifacts=local --target aarch64-apple-darwin` — the archive
  holds `canvas`, 51 man pages, and 5 completion scripts.
- `dist build --artifacts=global` — formula, source tarball, checksums.
- `cargo xtask dist-formula` on that formula, then `ruby -c` on the result:
  syntax OK.
- `brew install --build-from-source` was **not** run: it needs a release URL.
- `brew audit --strict` and `brew style` could **not** be run: `brew` 6.0.22 on
  this machine fails to load its own vendored `json` gem, so every developer
  command aborts before reading the formula (`brew --version` still works).
  Run them on the tap once it exists, per step 5 above.
